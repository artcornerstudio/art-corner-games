# WF-03 · Class Enrollment (private lessons, senior classes, group classes)

Owner: Instruction & Education Pod (17) · Priority default: P2 · Status: READY FOR APPROVAL

**Trigger:** enrollment inquiry for lessons or classes.

## Steps
1. **Intake** (`EDU-<id>`): student age group; experience level; interests/goals; accessibility needs (esp. seniors); schedule preferences; **minor → guardian is the contact; minimal-data rule applies** (first name, age group, guardian contact, allergies/accessibility if guardian offers — nothing more).
2. **Fit check** (pod): right class/level exists? If none scheduled → NURTURE list + digest note (demand signal for Analytics).
3. **Safety pass** (automatic for minors): data minimalism verified; photo policy communicated up front (CT-05); consent forms prepared — **photo use is a separate written consent + Jean gate**.
4. **Offer** (Customer Relations): class details, schedule (from Jean's stated availability only), price **from matrix** (missing → HOLD), enrollment form. → Brand/QA → Jean queue until acknowledgment policy grants exist.
5. **Enrollment confirmed:** roster updated; welcome packet (CT-06: what to bring, studio address in Antietam, expectations); payment recorded by Finance on Jean's confirmation.
6. **Ongoing:** attendance tracked; milestone notes; issues → Customer Experience.
7. **Closeout per term:** outcome summary to student/guardian; rebooking invitation timed to term end; Analytics record (retention).

## Fail-safes
- Enrollment form asking beyond minimal data = defect → Safety rewrites form (tested, A3 adjacent).
- No availability stated by Jean → offers HOLD; digest §9 asks Jean to set availability.
- Guardian requests curriculum with copyrighted characters ("can you teach them to draw Elsa?") → decline the copyrighted output warmly; teach original technique instead (CT-13 variant).
