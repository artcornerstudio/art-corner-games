# WF-11 · Customer Issue Resolution

Owner: Customer Experience (13) · Priority: P1 (safety-related: P0) · Status: READY FOR APPROVAL

**Trigger:** complaint, delivery problem, quality concern, billing dispute, or negative sentiment flag.

## Steps
1. **Log** (`ISS-<id>`): customer, issue verbatim, service lane, severity. Safety/rights/minor-related → **P0: freeze related outputs, Jean + Safety immediately.**
2. **Acknowledge:** empathetic acknowledgment draft within hours (CT-16) — regret + "we're looking into it now" + when they'll hear back. No fault admission, no remedy promises. PREPARE-tier (or approved-template policy once granted).
3. **Facts:** timeline from records; owning pod's account; QA root-cause note (what failed, which control missed it).
4. **Resolution proposal:** options with costs/implications. **Any remedy costing money or committing Jean (refund, discount, redo, deadline) = Jean gate.** Pure-communication remedies still pass Brand.
5. **Gate — Jean:** picks remedy (digest §1, or same-day escalation for P1).
6. **Deliver resolution:** approved message + remedy execution tracked to completion.
7. **Closeout:** customer confirms resolved (or documented decline); root-cause fix proposed to the relevant SOP; Risk Register entry if systemic; Analytics logs CSAT-after and time-to-resolution.

## Fail-safes
- Angry-customer pressure for instant compensation → empathy fast, remedies gated; speed comes from same-day Jean escalation, not from agents overstepping.
- Issue reveals a rights/consent breach → P0 path, incident procedure (`docs/08`).
- Repeat issue pattern (3+ same root cause) → systemic flag → Orchestrator schedules SOP fix.
